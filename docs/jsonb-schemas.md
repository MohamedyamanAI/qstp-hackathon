# JSONB Schemas Documentation

This document defines the expected structure (schema) for all `JSONB` columns used in the QSTP Incubation Platform database. Since PostgreSQL `JSONB` doesn't enforce a schema natively, the application layer (Zod) must enforce these structures when reading/writing to the database.

---

## 1. `profiles` Table

### `preferences`
Stores user-specific UI and notification settings.

```json
{
  "theme": "system", // "light" | "dark" | "system"
  "notifications": {
    "email": true,
    "push": true,
    "whatsapp": false
  }
}
```

---

## 2. `startups` Table

### `recipients`
Array of people who receive the generated updates (investors, board members, etc.).

```json
[
  {
    "id": "uuid-string", // Generated by the frontend/app
    "name": "John Doe",
    "email": "john@example.com",
    "role": "investor", // "investor" | "board" | "advisor" | "family"
    "preferred_format": "email", // "email" | "whatsapp" | "both"
    "frequency": "monthly", // "monthly" | "quarterly"
    "visibility_level": {
      "financials": true,
      "team": true,
      "pipeline": false
    }
  }
]
```

### `connected_integrations`
Tracks which third-party services the startup has connected for auto-pulling data.

```json
{
  "stripe": true,
  "github": false,
  "hubspot": false,
  "linkedin": true,
  "google_analytics": false
}
```

### `extended_profile`
Stores additional company information that doesn't need its own relational column.

```json
{
  "cr_number": "123456",
  "incorporation_date": "2024-01-15",
  "tax_regime": "QFC",
  "cap_table": [
    {
      "name": "Jane Founder",
      "ownership_percentage": 60.0
    }
  ]
}
```

### `privacy_settings`
Controls what data is visible to the portfolio/public.

```json
{
  "cohort_benchmarking": true, // Allow anonymized data in cohort comparisons
  "public_wins": true // Allow team to draft LinkedIn posts for wins
}
```

### `form_config`
Admin-controlled toggles to show/hide specific questions in the weekly/monthly KPI submission form.

```json
{
  "show_revenue": true,
  "show_mrr": true,
  "show_grants": true,
  "show_cost_savings": true,
  "show_elders_served": false, // Disabled for B2B SaaS
  "show_app_downloads": false, // Disabled for non-mobile apps
  "show_enterprise_reach": true
}
```

## 3. `kpi_submissions` Table

### `metrics`
The actual answers to the weekly/monthly report form. Only contains fields that are enabled in the startup's `form_config`.

```json
{
  "revenue_this_month": 15000,
  "mrr": 12000,
  "projected_revenue_next_month": 18000,
  "actual_revenue_this_month": 15000,
  "total_revenue_cumulative": 150000,
  "funds_raised_this_month": 0,
  "grants_received_amount": 50000,
  "grants_received_count": 1,
  "customer_cost_savings": 5000,
  "operational_cost_reduction_pct": 15.5,
  "elders_served": 0,
  "customers_reached": 120,
  "app_downloads": 0,
  "enterprises_reached": 3,
  "conversion_rate_pct": 5.5,
  "revenue_per_active_user": 45,
  "biggest_win": "Signed our first enterprise contract with Acme Corp!"
}
```

### `verified_fields`
Tracks which metrics were pulled automatically via integrations vs. entered manually.

```json
{
  "revenue_this_month": {
    "source": "stripe",
    "is_verified": true
  },
  "mrr": {
    "source": "stripe",
    "is_verified": true
  },
  "biggest_win": {
    "source": "manual",
    "is_verified": false
  }
}
```

### `generated_outputs`
The drafts and sent outputs generated by AI based on the submission.

```json
{
  "investor_email": {
    "status": "draft", // "draft" | "approved" | "sent"
    "subject": "October Update: Acme Corp",
    "body_html": "<p>Hi investors...</p>"
  },
  "linkedin_post": {
    "status": "approved",
    "content": "Thrilled to announce our new enterprise contract! 🚀"
  },
  "internal_slack": {
    "status": "sent",
    "content": "Great job team hitting 15k MRR this month!"
  }
}
```

---

## 4. `templates` Table

### `content`
The structure of a template used for generating outputs.

```json
{
  "subject_template": "{{month}} Update: {{startup_name}}",
  "body_template": "Hi {{recipient_name}},\n\nHere are our highlights for {{month}}:\n- MRR: ${{mrr}}\n- Biggest win: {{biggest_win}}\n\nBest,\n{{founder_name}}",
  "tone": "professional but optimistic"
}
```

---

## 5. `notifications` Table

### `content`
The payload for a notification, varying by `type`.

```json
// Example for type: 'new_opportunity'
{
  "title": "New Grant Match",
  "message": "MoCI Innovation Grant matches your profile.",
  "action_url": "/opportunities/123",
  "opportunity_id": "uuid-string"
}

// Example for type: 'team_feedback'
{
  "title": "New Feedback",
  "message": "Sarah commented on your October revenue.",
  "action_url": "/submissions/456",
  "submission_id": "uuid-string"
}
```
